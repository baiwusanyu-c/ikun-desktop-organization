# trellis-brainstorm - 需求发现

## 概述

在实现前引导协作式需求发现，针对 AI 编码工作流优化：
- **任务优先**（立即捕获想法）
- **行动先于提问**（减少低价值问题）
- **研究优先**（不让用户发明选项）
- **发散 → 收敛**（扩展思考，锁定 MVP）

当用户描述一个开发任务且需求不明确、有多种实现路径、或需要权衡时触发。

---

## 核心原则（不可协商）

1. **任务优先（早期捕获）**：始终先确保任务存在，用临时标题即可
2. **行动先于提问**：如果能从代码库、文档、配置中推导答案，先做再说
3. **每条消息一个问题**：不要用问题列表压倒用户
4. **偏好具体选项**：对于偏好/决策问题，提供 2-3 个可行方案及权衡
5. **研究优先**：如果决策取决于行业惯例或类似工具，先研究再提议
6. **发散 → 收敛**：初步理解后，主动考虑未来演化和边界情况，然后收敛到 MVP
7. **无元问题**：不问"应该搜索吗？"，直接搜索

---

## 步骤 0：确保任务存在（始终执行）

在任何问答前，确保任务存在。如果不存在，立即创建：

```bash
TASK_DIR=$(python3 ./.trellis/scripts/task.py create "brainstorm: <简短目标>" --slug <auto>)
```

立即用已知信息填充 `prd.md`：

```markdown
# brainstorm: <简短目标>

## 目标
<一段话：什么 + 为什么>

## 已知信息
* <来自用户消息的事实>
* <从代码库/文档发现的事实>

## 临时假设
* <待验证的假设>

## 待解决问题
* <仅保留阻断性/偏好问题，保持简短>

## 需求（演进中）
* <从已知信息开始>

## 验收标准（演进中）
- [ ] <可测试的标准>

## 完成定义（团队质量门槛）
* 添加/更新测试（单元/集成）
* Lint / typecheck / CI 通过
* 行为变更时更新文档/笔记
* 考虑发布/回滚（如果有风险）

## 明确排除范围
* <本任务不做什么>

## 技术笔记
* <检查的文件、约束、链接、参考>
```

---

## 步骤 1：自动上下文（提问前必须做）

在问"代码长什么样？"之前，先自己获取上下文：

### 代码库检查清单

- 识别可能受影响的模块/文件
- 找到现有模式（类似功能、约定、错误处理风格）
- 检查配置、脚本、现有命令定义
- 注意任何约束（运行时、依赖策略、构建工具）

### 文档检查清单

- 查找现有 PRD/规范/模板
- 查找命令使用示例、README、ADR（如有）

将发现写入 PRD：
- 添加到「已知信息」
- 将约束/链接添加到「技术笔记」

---

## 步骤 2：逐个提问

**一次一个问题**。每获得一个答案，立即更新 PRD。

### 好问题 vs 坏问题

| 好问题 | 坏问题 |
|--------|--------|
| "你更倾向 X 还是 Y？"（有具体选项） | "你觉得怎么样？"（太开放） |
| "这个边界情况怎么处理？" | "还有什么要考虑的吗？" |
| "性能优先还是可读性优先？" | "你有什么想法？" |

---

## 步骤 3：提议方案

对于架构决策，提议 2-3 个具体方案，各有权衡：

```markdown
## 方案对比

### 方案 A：<名称>
**优点**：...
**缺点**：...
**适用场景**：...

### 方案 B：<名称>（推荐）
**优点**：...
**缺点**：...
**适用场景**：...

### 方案 C：<名称>
**优点**：...
**缺点**：...
**适用场景**：...
```

---

## 步骤 4：确认最终需求

当需求清晰后：

1. 总结最终需求
2. 获得明确批准
3. 进入任务工作流（Phase 2+）

---

## 子任务分解

如果需求发现揭示了多个独立工作项，考虑使用 `--parent` 创建子任务：

```bash
# 创建父任务
PARENT_DIR=$(python3 ./.trellis/scripts/task.py create "<父任务>" --slug <slug>)

# 创建子任务
python3 ./.trellis/scripts/task.py create "<子任务1>" --parent "$PARENT_DIR"
python3 ./.trellis/scripts/task.py create "<子任务2>" --parent "$PARENT_DIR"
```
