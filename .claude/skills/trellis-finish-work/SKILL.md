# trellis-finish-work - 提交前检查清单

## 概述

在提交或归档代码前，执行完整的代码质量检查清单，确保工作完整性。

当用户说"完成工作"、"提交前检查"、"代码检查"、"准备提交"时触发。

**时机**：代码编写和测试完成后，提交前。

---

## 检查清单

### 1. 代码质量

```bash
# 必须通过
pnpm lint
pnpm type-check
pnpm test
```

- [ ] `pnpm lint` 无错误通过
- [ ] `pnpm type-check` 无类型错误
- [ ] 测试通过
- [ ] 无 `console.log` 语句（使用 logger）
- [ ] 无非空断言（`x!` 操作符）
- [ ] 无 `any` 类型

### 1.5. 测试覆盖

根据 `.trellis/spec/` 中的测试约定检查是否需要新增或更新测试：

- [ ] 新纯函数 → 是否添加了单元测试？
- [ ] Bug 修复 → 是否在 `test/regression.test.ts` 中添加了回归测试？
- [ ] 行为变更 → 是否添加/更新了集成测试？
- [ ] 无逻辑变更（仅文本/数据）→ 无需测试

### 2. 代码规范同步

**代码规范文档**：
- [ ] `.trellis/spec/backend/` 是否需要更新？（新模式、新模块、新约定）
- [ ] `.trellis/spec/frontend/` 是否需要更新？（新组件、新 hook、新模式）
- [ ] `.trellis/spec/guides/` 是否需要更新？（新的跨层流程、bug 教训）

**关键问题**：
> "如果我修复了一个 bug 或发现了不明显的行为，是否应该记录下来，以免未来的自己（或他人）再次遇到？"

如果是 → 更新相关的代码规范文档。

### 2.5. 代码规范硬性阻断（基础设施/跨层）

如果变更涉及基础设施或跨层契约，这是阻断性检查：

- [ ] 规范内容是可执行的（真实签名/契约），不是纯原则文字
- [ ] 包含文件路径 + 命令/API 名称 + payload 字段名
- [ ] 包含验证和错误矩阵
- [ ] 包含 Good/Base/Bad 用例
- [ ] 包含必需测试和断言点

### 3. API 变更

如果修改了 API 端点：

- [ ] 输入 schema 已更新？
- [ ] 输出 schema 已更新？
- [ ] API 文档已更新？
- [ ] 客户端代码已同步更新？

### 4. 数据库变更

如果修改了数据库 schema：

- [ ] 迁移文件已创建？
- [ ] Schema 文件已更新？
- [ ] 相关查询已更新？
- [ ] Seed 数据已更新（如适用）？

### 5. 跨层验证

如果变更跨多层：

- [ ] 数据在所有层间正确流动？
- [ ] 每个边界的错误处理正确？
- [ ] 类型在各层间一致？
- [ ] 加载状态已处理？

### 6. 手动测试

- [ ] 功能在浏览器/应用中正常工作？
- [ ] 边界情况已测试？
- [ ] 错误状态已测试？
- [ ] 刷新后仍正常工作？

---

## 快速检查流程

```bash
# 1. 代码检查
pnpm lint && pnpm type-check

# 2. 查看变更
git status
git diff --name-only

# 3. 根据变更文件，逐项检查上方清单
```

---

## 常见遗漏

| 遗漏 | 后果 | 检查项 |
|------|------|--------|
| 代码规范未更新 | 他人不知道变更 | 检查 .trellis/spec/ |
| 规范文本过于抽象 | 基础设施/跨层变更易回归 | 要求签名/契约/矩阵/用例/测试 |
| 迁移未创建 | Schema 不同步 | 检查 db/migrations/ |
| 类型未同步 | 运行时错误 | 检查共享类型 |
| 测试未更新 | 虚假信心 | 运行完整测试套件 |
| 遗留 console.log | 生产日志噪声 | 搜索 console.log |
