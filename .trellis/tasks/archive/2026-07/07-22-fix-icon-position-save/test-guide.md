# 图标位置保存Bug诊断测试指南

## 已添加的诊断日志

我已经在以下关键位置添加了 `[DIAG]` 前缀的诊断日志：

### 1. overlay_window.rs - save_overlay_icon_positions()
- 保存开始时的日志
- 保存前后的位置数量对比
- **位置丢失警告**：如果某个图标的位置在保存时丢失，会输出警告

### 2. drag_drop.rs - 拖拽操作
- `handle_box_to_box_move()`: 框→框移动开始和完成
- `handle_box_to_desktop()`: 框→桌面/覆盖操作开始
- `handle_drag_item_added()`: 目标框接收到项

### 3. icon_hider.rs - 图标仓库管理
- `ingest_icon()`: 图标收入仓库的过程
- `restore_all_hidden_icons()`: 还原所有隐藏图标的统计

### 4. app_runtime.rs - 程序退出清理
- `cleanup()`: 清理流程的各个阶段
- `merge_latest_overlay_config()`: 合并覆盖窗口配置前后的状态

## 测试步骤

### 场景1：从覆盖区域拖拽到分类框
1. 启动程序，确保桌面上有"微信"图标
2. 记录"微信"图标的当前位置（位置A）
3. 将"微信"从覆盖区域拖拽到一个分类框中
4. 退出程序
5. 检查"微信"图标是否回到位置A

### 场景2：从分类框拖拽到另一个分类框
1. 启动程序，确保"微信"已在分类框A中
2. 将"微信"从分类框A拖拽到分类框B
3. 退出程序
4. 重新启动程序，检查分类框配置是否正确保存

### 场景3：多次拖拽后退出
1. 进行多次拖拽操作（框→框，覆盖→框等）
2. 退出程序
3. 重新启动程序，检查所有图标位置是否正确

## 预期结果

如果bug存在，你应该会看到类似这样的日志：

```
[DIAG] save_overlay_icon_positions: 开始保存覆盖窗口图标位置
[DIAG] save_overlay_icon_positions: 当前覆盖窗口图标数=5, 保存位置数=10, 原有位置数=12
[WARN] [DIAG] save_overlay_icon_positions: 位置丢失! path=C:\Users\...\微信.lnk, pos=[100.0, 200.0]
```

这表明"微信"图标的位置在保存时被丢弃了，因为它已经从覆盖窗口移除。
