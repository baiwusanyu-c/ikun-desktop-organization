# 修复分类框重命名中文输入

## 目标
修复 Windows GPUI/Win32 分类框在修改名称编辑态下无法通过中文输入法输入中文的问题，保证英文、数字、中文 IME 提交、光标移动、删除、保存/取消等基础编辑行为稳定。

## 已知信息
* 用户反馈：分类框名称编辑态的输入框不能输入中文，需要仔细分析实现并可参考网络/GitHub。
* 项目为 Rust 桌面应用；分类框窗口是 Windows `WS_POPUP | WS_THICKFRAME` 分层窗口，输入框为自绘，不是原生 Edit 控件。
* 相关实现集中在 `src/platform/windows/wnd_proc.rs`、`src/platform/windows/grid_window.rs`、`src/platform/windows/d2d_render.rs`、`src/platform/windows/ffi_*`。
* 当前代码在编辑态拦截 `WM_KEYDOWN` 并对默认分支直接 `ToUnicode` 后返回 0；同时也处理 `WM_IME_COMPOSITION/GCS_RESULTSTR`。这可能阻断 IME 默认消息链或造成拼音按键被当作普通英文插入。
* Microsoft 文档说明：`WM_IME_COMPOSITION` 在组合状态变化时发送；若应用自己显示组合字符才处理，否则应交给 IME/`DefWindowProc`；`GCS_RESULTSTR` 是完成组合时可取出的结果字符串。

## 临时假设
* 根因很可能是编辑态吞掉了所有 `WM_KEYDOWN`，导致 IME 无法正常处理拼音按键/候选提交；普通字符输入可以通过 `WM_CHAR`，不应在 `WM_KEYDOWN` 默认分支手动 `ToUnicode`。
* 分类框窗口需要保持自绘输入框，但可以通过正确转发 IME 相关消息和处理 `GCS_RESULTSTR` 支持中文。

## 需求
- 编辑态中文输入法提交（如“中文”“测试”）能够插入到分类框名称中。
- 英文/数字/符号输入不回退；若消息循环缺失 `TranslateMessage`，仍有兼容路径。
- IME 组合期间不把拼音字母提前插入名称。
- 编辑态 Enter 保存、Esc 取消、Backspace/Delete/左右/Home/End 正常。
- 不引入 panic/unwrap/expect；遵循现有中文日志和 Win32 FFI 风格。

## 验收标准
- [ ] 代码明确区分控制键、IME 处理键和普通文本输入。
- [ ] `WM_IME_COMPOSITION/GCS_RESULTSTR` 插入 UTF-16 结果字符串，最多 16 个字符。
- [ ] 普通英文输入仍可插入。
- [ ] `cargo fmt` 通过。
- [ ] 尽可能运行相关 `cargo test` 或至少 `cargo check`（若环境限制则说明）。

## 明确排除范围
* 不重写为原生 Edit 控件。
* 不实现完整候选窗/组合中字符串自绘，仅保证最终提交中文能够进入输入框。
* 不调整分类框名称最大长度策略。
