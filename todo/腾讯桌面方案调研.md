## 腾讯桌面整理完整功能及对应呈现效果
一、基础格子收纳整理（核心主打功能）
1. 一键桌面智能整理
功能：一键自动扫描桌面全部快捷方式、文档、图片、压缩包、视频、安装包、文件夹，按照软件、文档、图片、其他文件四大类型自动分类收纳进独立格子；可开启长期自动监控，后续新保存到桌面的文件会自动归入对应格子，无需手动整理。
呈现效果：原本零散铺满桌面的图标瞬间收拢到 4 个半透明圆角收纳框内；格子默认横向排布，背景为低透明度灰色，不遮挡壁纸；桌面空白区域完全释放，整体干净规整；开启自动整理后，新文件不会再散落在桌面空白处。
2. 手动新建自定义格子
功能：用户自由创建收纳分区，可自定义格子名称（如工作项目、截图素材、安装包、学习资料）；可以自定义文件匹配后缀，把对应格式文件自动收纳进指定格子；格子支持拖动调整位置、缩放大小；配套 4 个快捷按钮：收起 / 展开、锁定位置、切换图标 / 列表视图、菜单设置；可随时解散格子，解散不会删除内部原文件，仅取消分区收纳。
呈现效果：桌面生成独立的半透明方框；收起时仅保留顶部标题栏，不占用桌面空间；展开后内部以图标或者列表模式展示文件；锁定后格子无法被鼠标拖动移位，防止布局打乱；多个格子可以自由排布，实现桌面分区管理。
3. 一键隐藏桌面全部图标
功能：双击桌面空白处，快速隐藏所有桌面图标与收纳格子；再次双击即可恢复显示，适合投屏、开会演示、录屏时使用。
呈现效果：桌面只保留壁纸，无任何图标、格子；双击后一键复原全部布局。

## 实现方案
核心关键点：
把 Explorer 里SysListView32中的真实桌面图标全部挪到屏幕外部，原生图标用户不可见；
每个收纳格子都是独立的WS_EX_LAYERED分层顶层弹窗；
图标不是系统原生的，全部在格子窗口的WM_PAINT中用 GDI+/D2D 自绘；
拖动格子本质是移动整个窗口句柄，内部图标依靠相对客户区坐标绘制，自然跟随窗口整体移动，不需要逐个移动原生图标；
只有发生拖入 / 拖出格子的操作时，才会同步修改底层真实文件的位置，并更新 PIDL 映射表。
简单对应第二部分各个步骤和方案二的绑定
步骤 1：获取桌面 ListView 句柄、Shell COM 接口，目的是枚举桌面文件并把原生图标移出可视区；
步骤 2：CreateWindowExW创建分层透明窗口，就是收纳格子的载体；
步骤 3：隐藏原生图标 + 自建内存结构体维护格子‑文件映射，是方案二的数据核心；
步骤 4 的拖拽逻辑：整体移动窗口，而非批量移动系统图标；只有拖入拖出才和原生图标交互；
步骤 5：自绘图标、方框，完全脱离 Explorer 原生列表；
步骤 6：监听 explorer 重启，防止资源管理器重启后原生图标复位。
## 方案细节简述
下面整体整理成适配 Rust‑Win32 的方案二完整架构，只保留核心逻辑、依赖、API 映射、结构体、关键流程，避开 C++ 专属写法，采用 winapi / windows‑rs 官方 Windows 绑定库。
整体逻辑完全对齐腾讯桌面整理的实现模式：隐藏系统原生桌面图标 + 分层弹窗作为收纳格子 + D2D/GDI 自绘图标 + 内存维护布局映射。

二、核心数据结构（Rust 版，内存层，核心）
原生桌面图标全部移出屏幕外，真实文件信息只存在内存，界面全部自绘。
rust
use windows::core::PCSTR;
use windows::Win32::Foundation::{HWND, POINT, RECT, LPITEMIDLIST};
use std::collections::VecDeque;

/// 单个收纳格子内部的文件项
#[derive(Debug)]
struct GridFileItem {
    pidl: LPITEMIDLIST,       // Shell唯一标识，不可丢失
    file_path: String,
    icon_handle: HICON,       //系统文件图标句柄，预加载
    client_offset: POINT,     //相对格子窗口客户区的坐标，整体移动窗口不需要修改此字段
}

/// 一个收纳格子，对应一个独立分层顶层窗口
#[derive(Debug)]
struct DeskGrid {
    hwnd: HWND,
    screen_rect: RECT,        //格子整体屏幕坐标
    items: Vec<GridFileItem>,
    title: String,
}

/// 全局桌面管理器单例
struct DesktopManager {
    explorer_lv_hwnd: HWND,   //SysListView32桌面图标列表句柄
    grid_list: Vec<DeskGrid>,
}
关键点：client_offset 是相对于窗口内部的局部坐标。拖动整个格子窗口，只修改窗口整体位置，不需要修改每一个图标的偏移；重绘时只需要基于窗口当前位置绘制，图标自然跟随窗口移动，这就是腾讯方案流畅的本质。
三、整体执行流程（严格方案二，分 5 步）
步骤 1：COM 初始化 + 抓取 Explorer 内部桌面 SysListView32 句柄
程序启动首先调用 CoInitialize(None) 初始化 COM；
通过逐层窗口遍历：Progman → WorkerW → SHELLDLL_DefView → SysListView32，拿到 explorer_lv_hwnd；
通过 COM 接口 IFolderView2 关闭桌面自动排列、网格吸附，否则资源管理器会把图标自动拉回屏幕可视区；
枚举桌面所有文件，获取每个文件的 PIDL；
发送 ListView 消息 LVM_SETITEMPOSITION，把所有原生图标移动到屏幕外部，例如 X = -3000，完成原生图标隐藏。
对应关键 Windows API，在 Rust 中通过windows‑rs调用：
FindWindowExW：逐层查找子窗口；
SendMessageW：发送LVM_SETITEMPOSITION；
COM 接口：IShellFolder、IEnumIDList、IFolderView2；
SHGetFileInfoW：获取文件图标 HICON、文件名。
步骤 2：创建收纳格子：WS_EX_LAYERED 分层弹窗（核心窗口配置）
每一个收纳格子都是独立的WS_POPUP无边框顶层窗口，不能是子窗口。
扩展样式必须固定：
rust
use windows::Win32::UI::WindowsAndMessaging::*;
let ex_style = WS_EX_LAYERED        //分层窗口，支持透明
    | WS_EX_TRANSPARENT             //空白区域鼠标穿透，可以点击底层壁纸
    | WS_EX_TOOLWINDOW;             //不出现在任务栏、Alt‑Tab列表

let class_name = PCSTR!("GridWindowClass");
//注册窗口类 RegisterClassExW
//调用CreateWindowExW 创建弹窗
创建后调用：
SetLayeredWindowAttributes，设置整体 Alpha 透明度，实现半透明背景框；
调用SetWindowPos，把窗口 Z 序置于 Explorer 桌面之上，低于普通应用窗口。
所有格子内部的图标、文字、圆角方框，全部在该窗口的WM_PAINT消息中，使用 Direct2D 自绘。
步骤 3：窗口消息循环与拖拽整体移动逻辑
窗口回调过程 (WNDPROC) 处理关键消息：
WM_LBUTTONDOWN：判断点击在格子标题栏，开启拖拽标记；
WM_MOUSEMOVE：如果拖拽标记开启，调用SetWindowPos整体移动窗口；仅更新窗口的屏幕位置，不会改动内部每个图标的client_offset；
WM_LBUTTONUP：结束拖拽；更新内存中DeskGrid的screen_rect；
WM_PAINT：触发 D2D 重绘：绘制圆角半透明背景、标题栏，遍历items，以相对客户区的client_offset绘制图标和文件名。
这就是拖动格子整体移动时图标一起移动的根本原因。
步骤 4：拖拽交互：文件拖入 / 拖出格子
这里依靠 Windows 的 COM 拖拽接口 IDropTarget，给每个格子窗口注册拖拽目标。
拖入文件到格子
获取被拖拽文件的 PIDL；
将原生系统图标再次挪到屏幕外侧；
把GridFileItem加入当前格子的items；
触发窗口重绘。
拖出文件到桌面空白区域
从格子的内存列表移除该项；
通过LVM_SETITEMPOSITION，将原生系统图标放回鼠标对应的桌面屏幕坐标；
系统原生图标重新可见；
格子窗口重绘。
步骤 5：监听 Explorer 资源管理器重启（必不可少）
当explorer.exe重启后，SysListView32窗口会重建，所有被隐藏的原生图标会复位回到桌面。
实现方式：通过 COM 接口IShellWindows注册事件监听，一旦检测到资源管理器重启，程序自动重新隐藏图标、重建所有格子窗口、加载内存布局。
四、Rust 里调用的核心 Win32 函数 / COM 接口清单（精简版）
1. 用户界面 API (user32)
RegisterClassExW：注册格子窗口类；
CreateWindowExW：创建分层弹窗；
SetLayeredWindowAttributes：透明度；
SetWindowPos：移动窗口、调整 Z 序；
FindWindowExW：遍历 Explorer 内部桌面窗口；
SendMessageW：发送 LVM 系列消息控制原生桌面图标；
InvalidateRect：触发重绘。
2. Shell COM 接口 (shell32)
CoInitialize / CoUninitialize：COM 初始化；
IShellFolder、IEnumIDList：枚举桌面文件 PIDL；
IFolderView2：关闭桌面自动排列；
IShellWindows：监听资源管理器重启；
IDropTarget：实现文件拖拽；
SHGetFileInfoW：获取系统文件图标。
3. 绘制模块（Direct2D，Rust 绑定）
使用windows‑rs的 Direct2D 接口，负责绘制圆角矩形背景、图标、文字；不建议使用 GDI，会出现拖动时的闪烁。
五、两种实现模式的避坑点（Rust 开发容易踩坑）
不要用子窗口做收纳格子，必须是独立顶层WS_POPUP弹窗；子窗口会被 Explorer 的桌面层级限制；
WS_EX_TRANSPARENT只让空白区域穿透，格子内部区域可以正常接收鼠标事件；
绝对不要依赖系统原生图标的位置，所有布局完全由内存的GridFileItem管理；
Explorer 重启事件必须监听，否则布局会直接失效；
PIDL 必须手动释放，Rust 中需要封装释放逻辑，避免内存泄漏。
